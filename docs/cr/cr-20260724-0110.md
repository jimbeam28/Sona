## 摘要

整体架构纪律良好：机械层零基线外违规、feature 隔离干净、覆盖率基线无漂移、密码安全硬约束基本守住。但功能层查出 **5 条 Critical/高影响缺陷链**，全部因测试结构性盲区（空壳测试 / 组合路径零覆盖 / helper 漂移）漏网：

1. **浏览器端进度记忆整体失效**（BRW1）：`loadProgressForDirectoryProvider` 只被 `invalidate` 从未被读取，Riverpod 对未创建元素的 invalidate 是空操作 → 进度注册表恒空 → 浏览页"续播对话框"与"清除进度"永不触发。
2. **启动即销毁多文件进度**（PRG2 = DB1 = CTR1 同根）：`findLatest()` 每次读前调 `migrateLegacyToLatest()` 物理删除除最新外的全部进度行，而写入路径是按文件多行模型——每次重启丢失所有非最近一首的进度记忆。根因是两套进度模型在同一张表混用，需用户裁决。
3. **恢复对话框 double-pop**（PRG1）：对话框关闭时 `.then(dismiss)` 触发退场动画期重建，null 分支 postFrame 再 pop 一次，误弹下层路由（/player 或 /browser），两个调用方均中招、必现。
4. **WebDAV basePath 约定自相矛盾**（NET1）：validate 替换 URL path、listDirectory 拼接 URL path 且无 basePath 参数，用户按任一方式配置基础路径都会在浏览/播放链路 404。
5. **shuffle 排列一致性缺陷簇**（PLY1/PLY3/MDL1/MDL4）：插入破坏排列、排列耗尽降级随机、shuffle 状态只写不读（重启丢序列）、手动选曲不更新 shufflePosition（MDL4 为 cr-2026-06-28 已报未修）。

次要风险面：契约层是名义抽象（六大接口消费方为零，CTR4）；FK pragma 只在 onCreate 置位致删单后孤儿行泄漏（DB2 = CTR8）；真实 WebDavClient HTTP 层零测试（NET9）；audio_handler 的 seek/setSpeed 缺 P4 超时兜底（SVC1）；connection 保存途中退出 ref-after-dispose 静默失效并可能产生重复连接（CON1）。

**测试健康度警示**：14 个模块中 11 个查出空壳/自证型测试（断言测试内自写的镜像逻辑而非生产代码），是上述缺陷系统性漏网的直接原因，建议与各模块 TEST-GAP 条目一并治理。

#### BRW1. 进度注册表从未被填充，浏览器端续播对话框与"清除进度"整体失效

### 2.1 screen 子模块（connection_screen / edit / list）

#### CON1. 保存/更新途中退出页面 → ref.invalidate 抛 StateError 被吞，新连接不生效且重试产生重复连接
- 类型 / 严重度 / 维度：BUG / Major / 并发时序（P9 变体：ref after dispose）+ spec S7
- 证据：`connection_screen.dart:197-209` `await saver.save(...)` 后裸 `ref.invalidate(activeConnectionProvider/connectionListProvider)`（无 mounted 守卫），同模式 `connection_edit_screen.dart:276-278`。Riverpod 2.6.1 `ConsumerStatefulElement.invalidate` 首行 `_assertNotDisposed()` 抛 StateError（release 也抛），被 `_onSave` 的 `catch (e) { if (mounted) ... }` 静默吞掉。
- 复现路径：播放器认证失败 → 点"检查连接"push /connection → 填好新连接测试成功 → 点保存在 1~2s 窗口内按返回 → save() 已落库但 invalidate 抛错被吞 → 两 provider 永久持旧值（非 autoDispose 无人再刷新）→ 本会话仍用旧连接 → 用户重填再存 → connections 表同服务器重复行，重启才自愈。编辑页同因：改活跃连接 URL 途中退出 → UI 旧值、DB 新值。
- 自检答案：分支零覆盖（fake DAO 瞬时完成无窗口，widget 测试从不模拟系统返回）。
