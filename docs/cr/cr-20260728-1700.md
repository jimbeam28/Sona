## 问题清单

### DESIGN

#### D1. audio_handler 焦点恢复 gained 分支死代码，文档与实际行为不一致

- 类型 / 严重度 / 维度：DESIGN / Minor / 功能-内部一致性
- 证据：
  - `lib/core/services/audio_handler.dart:78-93` `_initAudioSession` 只映射 `duck→transient`、`pause/unknown→lost`，**从不投递 `AudioFocusState.gained`**。
  - `lib/core/services/audio_handler.dart:197-211` `onAudioFocusChange` 的 `gained` 分支（`if (_config.isAudioActive && !_player.playing) play();`）——从未被触发，且即使被触发也不能恢复播放（见下）。
  - `lib/features/player/domain/background_playback.dart:158-163` `updateAudioFocus(gained)` 文档声称 "If we were playing before losing focus, resume"，但代码仅 `copyWith(audioFocus: AudioFocusState.gained)`，即**不恢复 playbackState**。丢失焦点后 `playbackState = paused`（`:166-168`），`isAudioActive` 恒 false，`play()` 分支永不执行。
  - 测试锁定行为：`test/features/player/ply_03_test.dart:1141` "lost → gained keeps paused"、`test/features/player/ref_13_test.dart:191` "gained focus restores focus flag but keeps paused"。
- 复现路径：无确定复现路径（死代码不会导致当前运行时错误）。条件：即使某条路径投递了 `gained`，恢复也不发生。
- 自检答案：纯层状态机测试正确断言了 "gained keeps paused"；无集成测试验证 `_initAudioSession` 的焦点事件映射（`AudioSession.instance` 在测试环境不可用，无 mock 覆盖）。
- 修复建议：二选一裁决——(a) 删 `onAudioFocusChange` 的 gained 分支（`lines 206-209`）并修正 `updateAudioFocus(gained)` 与 `_initAudioSession` 的文档注释，消除死代码和误导；(b) 如果希望实现通话结束自动恢复，`updateAudioFocus(gained)` 应在焦点之前是 `playing` 时恢复 `playbackState = playing`，并补 `_initAudioSession` 端对焦点结束事件的映射。

#### D2. playlist_dao findTracksForPlaylist 与 reorderTrack 的 ORDER BY 不一致

- 类型 / 严重度 / 维度：DESIGN / Info / 风格-内部一致性
- 证据：
  - `lib/core/database/dao/playlist_dao.dart:70` `findTracksForPlaylist`: `orderBy: 'added_at ASC'`（无 id tiebreak）
  - `lib/core/database/dao/playlist_dao.dart:104` `reorderTrack`: `orderBy: 'added_at ASC, id ASC'`（有 id tiebreak）
  - 两个方法查同一张表同一批数据，ORDER BY 子句不同。
- 实际影响：无。`addTracksToPlaylist` 与 `importPlaylist` 在批内使用递增 `+1ms` 时间戳（`playlist_service.dart:76, 172`），不同批次间的 `DateTime.now()` 也间隔至少秒级，所以 `added_at` 已是有效地唯一排序键。但两处不同 ORDER BY 是未来回归隐患（如改粗时间戳粒度时）。
- 修复建议：统一为 `added_at ASC, id ASC`（简单改 `findTracksForPlaylist` 的 orderBy 即可，与 `reorderTrack` 对齐）。

### TEST-GAP

#### T1. audio_handler 音频会话中断绑定无独立测试

- 类型 / 严重度 / 维度：TEST-GAP / Minor / 可测性
- 欠测行为：`lib/core/services/audio_handler.dart:78-93` `_initAudioSession` 是整个焦点处理管线的**输入源头**，但没有任何测试验证 `interruptionEventStream` 和 `becomingNoisyEventStream` 的事件到 `onAudioFocusChange` 的映射正确性。
  - `duck → transient` 映射从未被测试断言
  - `pause/unknown → lost` 映射从未被测试断言
  - 焦点结束事件（`event.begin == false`）的处理方式（当前忽略 `begin` 字段）无测试明确
- 建议锚定方式：使用 mock `AudioSession`（或在测试中用 `AudioSession.forTesting` 覆盖），注入伪造的 `interruptionEventStream` 与 `becomingNoisyEventStream` 事件序列，验证 `onAudioFocusChange` 被正确调用参数。
